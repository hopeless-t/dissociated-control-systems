# Human Control Dynamics — Deep Model

> Status: OPEN FORMALIZATION  
> Scope: HYP-007 support  
> Biological mechanism: MULTIPLE COMPETING ACCOUNTS  
> Training prescription authority: NONE

## Why this document exists

The Human Control Transition Ontology names state changes such as INDIVIDUATE,
CALIBRATE, REWEIGHT, PRUNE, ROBUSTIFY, and TRANSFER.

This document asks a harder question:

> What actually changed inside the controller, on what timescale, and how can
> competing explanations be distinguished when the visible performance change
> is the same?

The central warning is:

~~~text
same performance improvement
!=
same controller update
~~~

## 1. Controller factorization

Represent the slower learner state as:

~~~text
Theta_n = {
    P_n,   # physical / morphological capability
    B_n,   # accessible control basis / synergies
    O_n,   # observability map
    W_n,   # sensory weighting
    M_n,   # predictive / internal model
    Pi_n,  # control policy
    R_n,   # controllable / reachable state set
    V_n,   # variability structure
    H_n    # retained history / memory
}
~~~

Fast behavior is generated by:

~~~text
x_{t+1} = f(x_t, u_t, d_t ; P_n)
y_t     = h(x_t ; O_n) + noise
xhat_t  = E(y_0:t, u_0:t-1 ; W_n, M_n)
u_t     = pi(xhat_t, goal_t, context_t ; B_n, Pi_n)
~~~

Training updates Theta:

~~~text
Theta_{n+1} = T(Theta_n, practice_n, feedback_n, error_n, reward_n)
~~~

The update operator T is not assumed to be one mechanism.

## 2. Atomic update classes

A visible improvement can arise from different update classes.

### U-PHYS — physical capability update

~~~text
P_{n+1} != P_n
~~~

Examples may include strength, tissue tolerance, joint range, or other physical
changes.

### U-BASIS — control-basis update

~~~text
B_{n+1} != B_n
~~~

Examples include access to a previously hard-to-recruit movement component,
changed coupling among effectors, or a new task-specific synergy.

### U-OBS — observability update

~~~text
O_{n+1} != O_n
~~~

The learner becomes better able to detect a task-relevant state, either
naturally or through an augmented channel.

### U-WEIGHT — sensory-weight update

~~~text
W_{n+1} != W_n
~~~

The same sensory channels are available, but their relative influence changes
with reliability or task context.

### U-MODEL — prediction-model update

~~~text
M_{n+1} != M_n
~~~

The learner better predicts the consequence of action or perturbation.

### U-POLICY — policy update

~~~text
Pi_{n+1} != Pi_n
~~~

The mapping from estimated state to action changes without requiring a better
forward model.

### U-REACH — reachable-state update

~~~text
R_{n+1} != R_n
~~~

More task states can be controlled while satisfying declared performance and
risk constraints.

### U-VAR — variability-structure update

~~~text
V_{n+1} != V_n
~~~

Variance is redistributed between task-harmful and task-neutral dimensions.

### U-MEM — retention / retrieval update

~~~text
H_{n+1} != H_n
~~~

A solution is retained, recalled, or contextually selected more reliably.

A research result should prefer the narrowest update class supported by the
experiment.

## 3. Identifiability problem

Suppose task error improves:

~~~text
J_task(n+1) < J_task(n)
~~~

That observation alone cannot identify which component changed.

For example:

~~~text
better score
could be:
    stronger actuator
    better state estimate
    better prediction
    changed policy
    compensation
    external feedback dependence
~~~

Therefore HYP-007 requires intervention design.

Let candidate models be:

~~~text
M1 = policy change only
M2 = sensory reweighting
M3 = forward-model change
M4 = control-basis change
M5 = physical-capability change
M6 = compensatory solution
~~~

Then compare:

~~~text
P(data | M_k)
~~~

or held-out predictive error:

~~~text
E_test(M_k)
~~~

rather than assigning a transition label from performance alone.

## 4. Perturbation fingerprinting

Different controller updates should make different predictions under
perturbation.

Candidate probe families:

~~~text
sensory perturbation
    -> tests W / O

mechanical perturbation
    -> tests policy / prediction / robustness

feedback removal
    -> tests internalization vs dependence

context shift
    -> tests transfer / retrieval

component constraint
    -> tests control basis / compensation

dual-task load
    -> tests automatization / supervisory demand
~~~

A transition is better identified by its perturbation fingerprint than by its
training score.

## 5. Timescale hierarchy

Human control changes occur on multiple timescales.

~~~text
tau_0  within-movement correction
tau_1  trial-to-trial adaptation
tau_2  session learning
tau_3  retention / consolidation
tau_4  long-term skill restructuring
tau_5  physical / morphological adaptation
~~~

A minimal multi-timescale update is:

~~~text
Theta =
    Theta_fast
  + Theta_slow
~~~

with:

~~~text
Theta_fast(n+1)
=
    rho_fast * Theta_fast(n)
  + eta_fast * Delta_n

Theta_slow(n+1)
=
    rho_slow * Theta_slow(n)
  + eta_slow * Consolidate(Delta_n)
~~~

where typically:

~~~text
rho_slow > rho_fast
~~~

A large immediate gain with poor retention may therefore represent a different
transition from a smaller gain that survives feedback removal and delay.

## 6. Retention, hysteresis, and path dependence

Training state need not be a memoryless Markov ladder.

A more realistic model is:

~~~text
P(q_{n+1} |
    q_n,
    practice_n,
    history_0:n,
    context_n)
~~~

This permits hysteresis:

~~~text
state reached from A
!=
same-looking state reached from B
~~~

even if current task score is equal.

Candidate metrics:

~~~text
retention_after_delay
reacquisition_rate
context_switch_cost
washout_rate
spontaneous_recovery
~~~

## 7. Transition grammar

Transitions may have ordering constraints.

### Candidate productive composition

~~~text
DISCOVER
 -> ACCESS
 -> INDIVIDUATE
 -> CALIBRATE
 -> REINTEGRATE
 -> ROBUSTIFY
 -> INTERNALIZE-FB
 -> TRANSFER
 -> AUTOMATIZE
~~~

This is not a universal curriculum.

It is a grammar of testable dependencies.

For example:

~~~text
AUGMENT-OBS
 -> CALIBRATE
 -> INTERNALIZE-FB
~~~

is preferable to ending at:

~~~text
AUGMENT-OBS
 -> FEEDBACK-DEPENDENT
~~~

Likewise:

~~~text
EDGE-EXTEND
 -> REINTEGRATE
~~~

must be distinguished from:

~~~text
EDGE-EXTEND
 -> COMPENSATED-EXPANSION
~~~

## 8. Non-commutativity

Some transition operations may not commute.

Let T_A and T_B be training-induced update operators.

Then test:

~~~text
T_A(T_B(Theta))
!=
T_B(T_A(Theta))
~~~

Examples of research questions:

~~~text
INDIVIDUATE then REINTEGRATE
vs
REINTEGRATE under existing coupling then INDIVIDUATE

AUGMENT-OBS then CALIBRATE
vs
CALIBRATE then AUGMENT-OBS

PRUNE then ROBUSTIFY
vs
ROBUSTIFY then PRUNE
~~~

Order effects are a major untested part of the atlas.

## 9. Saturation and knees

A transition may have a useful operating range and a knee.

For practice dose d:

~~~text
Benefit(d) =
    TaskGain(d)
  + TransferGain(d)
  - Risk(d)
  - Dependency(d)
  - Fatigue(d)
~~~

A useful dose may satisfy:

~~~text
d_star = argmax_d Benefit(d)
~~~

The research target is not maximum practice dose.

It is the regime before marginal benefit is dominated by fatigue, compensation,
risk, or feedback dependence.

This intentionally borrows the knee-search discipline from Finite RAM Lab while
keeping the mechanism domain-local.

## 10. Exploration vs exploitation

Practice can serve two purposes:

~~~text
exploit:
    improve known solution

explore:
    learn which controller variables or solutions exist
~~~

For candidate probe p:

~~~text
Utility(p) =
    alpha * expected_task_gain
  + beta  * information_gain
  + gamma * expected_transfer
  - lambda * risk
  - mu * cost
~~~

with:

~~~text
information_gain =
    I(Theta ; Y | p)
~~~

Elite training may differ partly in how it allocates practice between
exploitation and information-seeking.

## 11. Representative robustness

More variable practice is not automatically better.

Let:

~~~text
P_train(d) = perturbation distribution during practice
P_test(d)  = perturbation distribution in target environment
~~~

Robustification should be evaluated relative to overlap / relevance between
these distributions.

A generic distribution-shift term is:

~~~text
D_shift = D(P_train || P_test)
~~~

where D may be a declared divergence / distance appropriate to the data.

The prediction is:

~~~text
randomness alone != transfer
representative variation is the stronger target
~~~

## 12. Feedback guidance and dependency

Augmented feedback can improve task performance while leaving unresolved
whether the learner internalized the control variable.

Define:

~~~text
J_on  = performance with augmented feedback
J_off = performance after feedback removal
~~~

and:

~~~text
Dependency =
    J_on - J_off
~~~

A successful AUGMENT-OBS pipeline should eventually reduce dependency:

~~~text
AUGMENT-OBS
 -> CALIBRATE
 -> INTERNALIZE-FB
~~~

not merely maximize J_on.

## 13. Compensation model

Let desired output be:

~~~text
z = g(x_1, x_2, ..., x_m)
~~~

A learner may improve z by changing the target subsystem or by shifting load
to another subsystem.

Represent subsystem effort / exposure:

~~~text
l = [l_1, ..., l_m]
~~~

A genuine target expansion should produce the declared output gain with bounded
off-target load growth.

Candidate compensation index:

~~~text
CI =
    off_target_load_increase
    /
    target_control_gain
~~~

The exact load definition is domain-specific.

The key requirement is to measure hidden redistribution, not only visible
output.

## 14. Transition signature vector

Each experiment can report:

~~~text
Delta = [
    d_task,
    d_transfer,
    d_retention,
    d_obs,
    d_ctrl,
    d_variance_task,
    d_cost,
    d_dependency,
    d_risk
]
~~~

This permits cross-domain comparison without claiming identical mechanisms.

## 15. Competing theoretical families

HYP-007 should remain compatible with multiple motor-control accounts.

### Internal-model / optimal-control family

Emphasizes:

~~~text
prediction
state estimation
cost
feedback correction
policy
~~~

### Ecological / constraints-led family

Emphasizes:

~~~text
perception-action coupling
affordances
task constraints
environmental information
self-organization
~~~

### Active-inference family

Emphasizes:

~~~text
prediction
uncertainty
sensory precision
action as prediction-error reduction
~~~

The atlas should use these as competing explanatory families where they make
different predictions.

A shared equation is not evidence that one theory has won.

## 16. Ordinary-adult research lane

The useful general-person claim is deliberately narrow:

~~~text
some control properties are trainable
~~~

not:

~~~text
elite methods create a general human upgrade
~~~

A safe experiment should separately test:

~~~text
acquisition
retention
feedback removal
representative perturbation
held-out transfer
compensation
~~~

The unit of success is a verified transition, not a difficult exercise.

## 17. Strongest near-term validation

A synthetic or low-risk behavioral validation should attempt to recover known
labels from data.

Example design:

~~~text
Arm A: repeated fixed task
Arm B: augmented feedback
Arm C: representative perturbation
Arm D: feedback fading + held-out transfer
~~~

Fit competing state-space models and ask whether the inferred transition
sequence predicts the held-out phase.

The key milestone is:

~~~text
predict before observe
~~~

not retrospective storytelling.

## 18. Correction is not learning

The deep model distinguishes execution-time error correction from persistent
controller change.

~~~text
CORRECT
    current movement is rescued by feedback

ADAPT
    next trials change because of prior error / perturbation

CONSOLIDATE
    acquired change survives time without equivalent practice

RETAIN
    delayed test still expresses the change

TRANSFER
    the change appears in a held-out neighboring condition
~~~

Therefore:

~~~text
good performance with live feedback
!=
motor adaptation
!=
retained learning
!=
general transfer
~~~

This distinction should be enforced in evidence tables and README claims.
