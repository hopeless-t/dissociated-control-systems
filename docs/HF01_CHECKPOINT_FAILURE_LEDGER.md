# HF01 Checkpoint Failure Ledger

The four current must-pass roles are not retained because they sound prudent.

Each one is tied to a failure that actually occurred during HF01.

## Provenance

Observed failures:

- Cuffdiff contrast orientation could be interpreted backwards.
- A vendor fold-change label in GSE178510 was ambiguous enough to support two
  plausible sign readings.

Repair:

- derive direction from primitive sample labels/signals;
- freeze known-answer tests.

This role prevents measurement semantics from disappearing during compression.

## State vs response

Observed failure:

A cross-sectional WNT/regeneration disease-state projection was reused as if it
were automatically a monotonic minoxidil-response coordinate.

The pre-registered prediction failed.

Repair:

~~~text
State Separation Axis != Actuator Response Axis
~~~

This checkpoint exists because HF01 itself made the mistake.

## Uncertainty / claim ceiling

Observed failure class:

Published mechanisms can be real while the chosen observer fails.

Examples include the current whole-tissue androgen and vascular transcript
projections.

Repair:

~~~text
mechanism support
!= observer validation
!= endpoint authority
~~~

This checkpoint preserves UNKNOWN, mixed evidence, and rejected observers.

## Reachability

Observed failures:

- identical current visible output can hide opposite futures;
- a positive early internal response can occur in a synthetic locked state with
  essentially no late output recovery.

Repair:

~~~text
State != Reachability
Early Response != Reachability
~~~

This checkpoint forces the target question to remain explicit.

## Removal rule

A mandatory role can be removed only if another enforced role or protocol:

1. blocks every known failure currently assigned to it;
2. does so with equal or stronger fail-closed semantics;
3. lowers total path cost;
4. does not create a new bypass path.

This turns checkpoint permanence into an empirical engineering decision rather
than tradition.

## Scope

The ledger shows that the four roles are currently justified against known
HF01 failures.

It does not prove that four roles are universally sufficient.

New failure classes may add or restructure barriers.
