# HF01 Last Responsible Checkpoint Placement

A mandatory checkpoint can still be badly placed.

If it is shown too early, it creates friction while the information is not yet
needed.

If it appears after the unsafe transformation, it is no longer a forcing
function.

## Rule

For each known failure mode define the first operation where the error can
become consequential.

Place its gate at the latest point that still dominates that operation.

~~~text
too early:
    safe but unnecessarily expensive

last responsible moment:
    safe and minimum declared exposure cost

too late:
    invalid
~~~

## HF01 examples

### Provenance

The user does not need a full provenance lecture at every molecular diagram.

But before an observed number is promoted into an empirical claim, source and
measurement semantics must be available.

### State vs response

This gate should appear immediately before a state-separating feature is used
to reason about intervention response.

The GSE178510 failure identifies this hazard boundary.

### Uncertainty

Uncertainty must become explicit immediately before an inference is promoted in
authority.

### Reachability

Reachability is unnecessary for a purely descriptive data statement.

It becomes mandatory immediately before the system emits a recovery,
restoration, or target-reachability claim.

## Consequence

The mandatory skeleton is not a static four-slide sequence.

It is a set of role barriers injected just-in-time according to the endpoint
claim and the next potentially unsafe transformation.

This gives:

~~~text
minimum mandatory semantics
+
minimum mandatory exposure duration
~~~

which is a stronger compression target than simply minimizing checkpoint count.
